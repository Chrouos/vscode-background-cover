# Dynamic Background Loader Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the external background runtime load in current VS Code desktop workbench renderers that enforce Trusted Types.

**Architecture:** Keep the small bootstrap injected into VS Code's workbench bundle, but change its runtime-loading boundary from direct `import(vscode-file://...)` to `fetch` plus a Blob-backed module import. The runtime source is still generated by `FileDom`; a pure helper exposes the loader snippet so the failure mode is covered by a fast unit test without starting VS Code.

**Tech Stack:** TypeScript, Node.js `assert`, VS Code extension workbench patching, Blob-backed ECMAScript modules.

## Global Constraints

- Preserve the existing bootstrap marker and cache-busting behavior.
- Do not reintroduce string-based `<script src=...>` injection because the target workbench requires Trusted Types for script sinks.
- Keep the fix limited to the dynamic loader and its regression coverage.
- The PR must target `master` and be opened as a draft.
